# ontoKBv2 个人记忆 Agent

需求文档 v2 · 10 个工作日 · 中文确认版 · 2026-09-28

## 1 项目目标

交付一个以 **Codex harness 为中心**、小而可用的个人记忆 Agent。用户通过对话保存资料、获取有引用的回答、将知识纳入个人记忆并更新判断。对话和受控工具是主要入口，不要求新建 Web application。

以提供的 LOGOS 快照为强类型对象、可执行 Action 和审计的蓝本，复用 ontoKB 的 Python、SQLite、证据和记忆代码。TEBIS 的关键教训是：类型和 Action 不能只有声明，必须由运行时代码执行约束。交付个人场景中的企业级本体核心语义，不宣称完整企业平台成熟度或等同 Palantir。

**本 v2 文档独立定义 10 日版的全部范围与验收标准。** 原[需求文档](PROJECT_REQUIREMENTS_ZH.md)、本体设计及验收计划原样保留，作为完整路线图；其中额外要求不构成本次交付义务。

## 2 范围与缩减

限定为单用户、单本地 Windows 工作区、中英文文本、一个配置好的模型和一条 Codex 集成路径。优先复用现有 app-server 接入与限定宿主工具，仅做完成下述流程所需修改；本期不同时建设第二条集成路径，不将后端迁到 TypeScript。

| 10 日内交付 | 延后 |
|---|---|
| 粘贴正文、UTF-8 TXT/Markdown | URL 抓取、PDF/OCR、视频/音频接入及连接器 |
| 自动候选抽取、校验、证据关联和去重 | 自动事实核实、置信度校准、自动纳入个人记忆 |
| 资料库/个人记忆分范围问答、用户管理判断 | 自动发现冲突、时间查询引擎、实体合并/拆分、任务管理 |
| 固定强类型 schema、四个 Action、回执和重试保护 | 动态本体设计器、发布管理器、多 Agent 编排、微调 |
| 本地启动脚本、样例、备份恢复、旧数据副本升级检查 | 安装器、新后台、定时任务、云端/团队部署、SSO、HA |

范围外已有功能可保留，但不增加开发，也不能成为验收依赖。有歧义的身份保持分离；冲突论断保留各自来源，Agent 不得静默覆盖论断或用户立场。

## 3 核心需求

| 编号 | 必需行为 |
|---|---|
| R-01 | 在 Codex 对话及限定工具中完成收集、有据问答、记忆纳入、判断修改、记忆排除；演示必须有真实工具执行，不能只有生成的回答。 |
| R-02 | 自动将支持的正文处理为带来源候选，保留原文、标题、可选来源 URL 元数据、采集时间及内容哈希；相同提交复用已完成结果，正文变化产生不可变新快照；无效或失败抽取明确显示。 |
| R-03 | 实现六类可见对象：SourceDocument、Person、Organization、Concept、Claim、PersonalMemory。具备稳定 ID、schema 版本及 revision，写入前校验属性类型、必填字段和强类型引用；证据片段、判断历史可作为辅助记录。 |
| R-04 | 每个 Claim 关联来源快照中的准确原文与字符范围；使用 mentions、about、supportedBy 等强类型关系。不能因名字相同将 Person 当作 Organization；缺证或无效关系不能进入已接受记忆。 |
| R-05 | 区分“资料库”和“我的记忆”查询；资料库回答说明抽取论断的来源，个人记忆仅使用用户纳入记录并显示立场。引用证据，缺证时澄清或拒答。 |
| R-06 | 将 CaptureSource、AcceptMemory、ReviseJudgment、ExcludeMemory 实现为可执行 Action Type；来源论断、个人纳入和 agree/question/disagree/undecided 立场分离；保留判断修改前后历史，自动化不能代替用户表态。 |
| R-07 | 每个 Action 校验强类型输入、可信本地用户身份、允许状态、目标版本及幂等键；语义修改与回执原子提交，重试不重复副作用。来源文本不能授权写入；Agent 核对回执后才宣称成功。 |
| R-08 | 提供启动/配置说明、一套 skill/指令与限定工具；凭证和私有数据不入代码。升级 v1 数据副本前备份，保留人工修正、排除及判断历史，列明不支持记录并演示恢复，不能修改唯一原件。 |

最小强类型示例：Claim 包含 `text: string`、`source_id: SourceDocument reference`、`quote: string` 和整数片段范围；PersonalMemory 包含 Claim 引用、`included: boolean`、受控 stance 枚举及 `revision: integer`。辅助历史记录保留旧值。代码必须拒绝无效值和错误引用类型，仅有标签或 YAML 不能满足 R-03/R-04。

最小 Action 示例：AcceptMemory 接收 Claim ID、预期版本和幂等键，检查用户授权与证据，记录纳入但不代表认同，返回新版本和回执。同 key 同参数重试返回原结果，同 key 不同参数或过期版本拒绝。ExcludeMemory 从个人回忆范围排除该论断，但保留来源知识及历史。

## 4 实施方式

**Codex harness → 限定宿主工具 → 强类型校验与 Action handler → SQLite → 证据及回执。** 只有一个权威写入边界，在现有代码上增加固定版本 schema 和 handler，不复制 LOGOS 整套服务。CaptureSource 内部候选处理也经过统一校验与审计。检索先复用关键词/实体查询，不要求向量检索。

run ID、已完成阶段标记和回执独立于对话持久保存；重启后先核对已提交 Action 再重试，未完成收集可安全重跑。支持工具调用间停止并说明部分完成，超时不能当作未写入的证明。初始每用户任务最多 8 次工具调用、失败阶段重试 1 次、含工具时间总限时 120 秒；超长输入明确拒绝。第 1 日设定数字化用量预算，记录消耗，到上限停止新模型任务。说明登录/模型前提及远程推理的数据外发；日常使用无需编辑数据库或 schema。

## 5 验收

准备 20 份获准或合成文档，中英均衡：10 份开发、10 份锁定验收，按来源家族隔离。第 2 日前准备标注。锁定集包含 100 条预期强类型、有证据断言，以及 40 个问题：30 个可回答，10 个歧义/缺证。金标答案不进入检索或提示词。这是小范围版本门槛，不是普遍精度的统计保证。

| 编号 | 通过条件 |
|---|---|
| A-01 Harness 流程 | 经 Codex 演示收集 → 有据问答 → AcceptMemory → ReviseJudgment → ExcludeMemory，验证实际数据、历史、回执，无需强制后台。 |
| A-02 抽取与自动化 | 至少 8/10 份锁定来源无需手工编辑即生成有效候选；输出断言中至少 95% 的类型、关系及支持片段正确，且找回至少 80/100 条预期断言；不能用模型自报置信度评分。 |
| A-03 回忆质量 | 至少 27/30 个可回答问题完整正确且引用支持；至少 9/10 个歧义/缺证问题合理澄清或拒答；分语言报告，失败和超时不从分母剔除。 |
| A-04 受控执行 | 30 个固定测试全部通过：覆盖每个 Action 的合法、无效输入、无权限、过期状态，并覆盖重放、重启、注入和记忆范围隔离；零越权写入、重复副作用、静默改立场、虚报成功。 |
| A-05 恢复与交接 | 连续 2 小时反复收集/问答并强制重启一次，无已提交记录丢失；恢复备份，逐项对账选定旧数据为已保留或明确不支持；一位非开发用户按指南完成样例流程。 |

调优前冻结样例与门槛。保留原始结果、观测延迟及用量，不另开性能优化项目。第 10 日仍未通过的项目如实列明及记录剩余工作，不能因到期就算验收。旧版大规模基准、24 小时运行及完整企业发布门槛延后。

## 6 十个工作日计划与交付物

由一位有经验工程师投入 **10 个工作日**，产品拥有者/评审配合标注及验收。开始前具备源码权限及可用 Codex/模型账号。复用现有代码，不重写平台。

| 日期 | 工作及退出结果 |
|---|---|
| 第 1–2 日 | 确定范围、private 仓库、可用 harness 路径和基线；准备样例、固定 schema 与 Action 契约。 |
| 第 3–4 日 | 实现校验器、四个 Action handler、回执、版本检查和持久幂等。 |
| 第 5–6 日 | 经 Codex 工具串联收集/抽取、证据、两类问答范围和判断历史。 |
| 第 7 日 | 旧数据副本升级检查、备份恢复、重启对账、失败处理。 |
| 第 8 日 | 执行锁定质量评测及受控操作测试，记录缺陷。 |
| 第 9 日 | 修复并重跑相关测试，完成 2 小时运行和用户指南。 |
| 第 10 日 | 最终验收演示、原始结果、限制说明和交接。 |

只交付四组成果：**可运行代码及配置、skill/工具和固定 ontology/Action 契约、样例及测试结果、简短用户/恢复指南和验收清单**。不另建大型文档套件。本期是有边界的核心版本，延后能力作为后续工作。

## 7 仓库提示

项目计划开源，但**开发时先创建 private 仓库**。公开前检查复用许可证、凭证及个人资料，使用可分发样例。本规格文档不代表已创建远程仓库，也不代表实施已经通过验收。
